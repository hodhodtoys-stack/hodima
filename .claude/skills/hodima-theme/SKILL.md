# قانون‌های قالب هدیما (`hodima/`)

قالب فقط نمایش است؛ منطق تازه (اسکیما، داده، امنیت، پیشخوان، کش) در افزونه‌ها (اسکیل `hodima-plugins`). تاریخچه هر بخش: `HODIMA-AUDIT.md` با شماره بخش داده‌شده.

## ساختار
- `hodima/`: قالب (نسخه در `style.css`) — فقط نمایش: هدر/فوتر، صفحه اصلی (`home/`؛ چیدمان: `inc/home-layout.php` + `front-page.php`، تب «صفحه اصلی» تنظیمات)، قالب‌های ووکامرس، «نمایش ← تنظیمات قالب هدیما» (`inc/theme-settings/`)

## پالت رنگ برند
**پالت رنگ برند** (توکن‌ها در `hodima/assets/css/tokens.css`؛ مدیر از «تنظیمات قالب ← برند» عوضش می‌کند):
   `#25316a` (اصلی) · `#607bbd` · `#b6c2f3` · `#6a2b9a` · `#a341c8`
   در CSS قالب رنگ برند ثابت ننویس: `var(--hodima-primary, #25316a)` و برای نیمه‌شفاف `rgba(var(--hodima-primary-rgb, 37, 49, 106), 0.1)` (بخش ۵۵).

## قانون‌ها
- **CSS قالب (از 2.9.2، بخش ۶۲):** سورس مدرن (nesting، color-mix با رنگ ثابت…) و مرورگرهای قدیمی با مرحله ساخت (`browserslist` در `package.json`). `@media` فقط بازه‌ای با `<=`/`>=` (مثلا `(width <= 768px)`، مکمل `(width >= 993px)`)؛ `<`/`>` و `@layer` ممنوع (ساخت رد می‌شود). نقطه‌های شکست، شعاع (`--hodima-radius-*`)، فاصله (`--hodima-space-1..9`) و سایه (`--hodima-shadow-*`، `--hodima-ring`) در `tokens.css`؛ مقدار ثابتی که توکن دارد را با توکن بنویس. پیشوند `-webkit-` همیشه **قبل** از خصوصیت استاندارد (برعکسش را minify حذف می‌کند). JS پایین آورده نمی‌شود: `matchMedia` با `min-width`/`max-width` همان عدد CSS. از 2.9.3 (بخش ۶۳): nesting و خصوصیات منطقی چپ/راست در همه فایل‌ها (استثنا: عنصر `direction: ltr` و گوشه‌های radius)؛ زیر انتخابگر چندتایی `&:hover` ننویس (`:is()` می‌شود). `color-mix(var)`، container query، `:has()` و `@layer` تازه ننویس: پایین آورده نمی‌شوند و Chrome 109 (ویندوز ۷) و Safari 14/15 کل قانون را نادیده می‌گیرند؛ رنگ نیمه‌شفاف برند همان `rgba(var(--…-rgb), a)`، رنگ ثابت `rgb(0 0 0 / 0.1)`. `!important` تازه فقط با دلیل (رقیب ووکامرس/افزونه)؛ `tools/wp-harness/important-audit.sh` زائدها را پیدا/حذف می‌کند. از 2.9.5 (بخش ۶۵): CSS همه صفحه‌ها فقط در `HODIMA_COMMON_CSS` (`inc/enqueue.php`؛ ZIP آن را یک فایل `hodima-common.css` می‌کند، handleهای قبلی نام مستعار) و پیش از CSS هر صفحه لود می‌شود. CSS حیاتی فقط با ماژول `inc/performance/critical-css.php` (از 3.8.0، بخش ۱۸۴؛ CCSS لایت‌اسپید به QUIC.cloud نیاز دارد که در ایران وصل نمی‌شود): CSS حیاتی دستی/دوم در قالب ننویس؛ stylesheet تازه خودکار preload می‌شود، پس اگر نباید async شود `data-no-async` بگیرد؛ با لایت‌اسپید (از 3.8.1، بخش ۱۸۵) async فقط روی خروجی نهایی (`litespeed_buffer_finalize` اولویت ۲۵) است، نه `style_loader_tag` — preload پیش از ترکیب، ترکیب لایت‌اسپید را دور می‌زند (CLS ۰٫۹ زنده)؛ هر تغییر سازنده (`assets/js/critical-css-admin.js`) را با CSS کُند (تأخیر ۴ثانیه) در ۳۹۰/۸۲۰/۱۰۲۴/۱۳۰۰ و نسخه ZIP بسنج: صفحه «فقط CSS حیاتی» = صفحه نهایی و CLS = حالت عادی. محافظ `#hodima-ccss-guard` (`body>*{overflow-x:clip}` تا flip؛ از 3.8.3، بخش ۱۸۷) را برندار: بدون آن در RTL بیرون‌زدگی افقی بخش‌های بی‌استایل CLS ≈۱ می‌سازد؛ در آزمون `document.body.scrollWidth` را هم بسنج.
- **PHP قالب (از 2.9.0، بخش ۶۰):** هر فایل `declare(strict_types=1)`؛ نوع ورودی/خروجی همه توابع (کال‌بک هوک وردپرس: ورودی `mixed` و تبدیل داخل تابع)، **کلوژر و arrow function هم** (`static function ( mixed $x ): mixed`، `static fn( int|float $c ): float`؛ `bash bin/lint.sh` با `tools/quality/closure-types.php` بدون baseline می‌گیرد، بخش ۱۵۹)؛ baseline PHPCS/PHPStan قالب **خالی** است، پس هر خطای PHP جدید CI را قرمز می‌کند. کلاس/enum جدید در `hodima/inc/classes/` (یک ساختار در هر فایل؛ لود در `hodima_load_theme_files()` در `functions.php`). CSS/JS قالب فقط با `hodima_enqueue_asset( handle، مسیر نسبی )`. اسکریپت قالب: `'in_footer' => true, 'strategy' => 'defer'` بومی؛ فیلتر `script_loader_tag` که `defer` را در رشته تگ بنویسد ممنوع است (وابستگی‌ها را نمی‌بیند، بخش ۱۵۵). `phpcs:ignore` همیشه با نام قاعده و ` -- دلیل`. متغیر در قالب‌های سطح بالا (single-post، archive-blog، template-page-videos، front-page…) پیشوند `hodima_` (در فضای سراسری PHP اجرا می‌شوند).
- **تایپوگرافی (از 2.9.6، بخش ۶۶):** فونت، اندازه/فاصله خطوط/رنگ متن، لینک و تیترهای H1–H6 فقط از توکن‌های `tokens.css` (`--hodima-font`، `--hodima-font-heading`، `--hodima-body-*`، `--hodima-link*`، `--hodima-hN-*`)؛ نام فونت یا اندازه تیتر پایه ثابت ننویس. تب «تایپوگرافی» (`inc/typography.php` + فیلدهای `hodima_typography_fields()`) فقط مقدار متفاوت با پیش‌فرض را بعد از tokens.css چاپ می‌کند (مثل پالت)؛ پیش‌فرض فیلدها = مقدار tokens.css (هر دو را با هم عوض کن). قانون‌های تیتر در `style.css` و `assets/css/editor.css` (ویرایشگر) یکی‌اند. تیتر یک جزء (کارت، قاب کناری) که نباید با پله‌های پایه عوض شود اندازه خودش را بگیرد. **عنوان h1 هر صفحه** (از 2.9.9، بخش ۷۲) اندازه/وزن/رنگ/فاصله خطوط ثابت ندارد و از قانون پایه `h1` می‌گیرد؛ اگر کلاسی که روی h2 هم هست باید روی h1 تنظیم H1 را بگیرد: `var(--hodima-heading-size)` و بقیه متغیرهای سطح.

- **جاوااسکریپت (از 3.7.2، بخش ۱۷۵):** سورس مخزن خوانا و بدون minify؛ فقط ZIP با `bin/build-js.mjs` (esbuild) کوچک می‌شود. فایل تازه JS باید داخل IIFE باشد (هیچ `function/var/let/const` در ستون صفر: نام‌های سطح بالا عوض نمی‌شود) و `eval`/`new Function` نداشته باشد. بعد از تغییر JS: `bash bin/build.sh` و `tools/wp-harness/js-equiv.mjs` (راهنما در README ابزار) باید ۰ تفاوت بدهد. `content-visibility` فقط همان بخش‌های صفحه اصلی که هست؛ برای فوتر/محصول سنجیده و رد شد (سود در نویز، ارتفاع صفحه می‌پرد، جعبه بازشونده ارتفاع را اندازه می‌گیرد).
- **تب «پیج اسپید» و sizes کارت (از 3.7.5؛ تب جدا از «تنظیمات ویدئو» از 3.7.7، بخش‌های ۱۷۸ و ۱۸۰؛ خلاصه کارها: `docs/pagespeed.md`):** تنظیم تازه‌ای که فقط سرعت/PageSpeed را عوض می‌کند در تب `pagespeed` (قاب‌های `pagespeed_scripts`، `pagespeed_images`)؛ تب `speed` («تنظیمات ویدئو») فقط دامنه پخش رسانه است (`speed_preconnect`) و با توضیح «کدام مورد PageSpeed را بهتر می‌کند»؛ کلید ذخیره‌شده را برای انتقال بین تب‌ها عوض نکن. `inc/performance/card-image-sizes.php`: رشته `sizes` کارت فروشگاه/دسته از شبکه ستون‌های `shop-page.css` است (۲/۳/۴/۶ ستون)؛ با عوض شدن ستون‌ها یا فاصله‌ها، رشته را هم به‌روز کن و عرض واقعی کارت را در Chromium روی چند عرض بسنج (فرمول باید همیشه ≥ عرض واقعی باشد).
- **فونت وزیرمتن (از 3.7.1، بخش ۱۷۳):** هر وزن دو فایل دارد — `Vazirmatn-<وزن>-base.woff2` (کوچک) و فایل کامل — با `unicode-range` در `style.css`؛ دو بازه هم‌پوشانی ندارند. فایل کامل را حذف نکن (نویسه‌های نادر، پیشخوان، ویرایشگر). وزن یا فایل تازه: `pip install fonttools brotli && python3 tools/fonts/make-base-fonts.py --write` و خروجی چاپی را جای `@font-face`ها بگذار؛ بعد صفحه نمونه نسخه جدید در برابر فقط-کامل باید ۰ پیکسل متفاوت و `visual-compare.sh` یکسان باشد. preload فایل `-base` را می‌دهد. از 3.8.7 (بخش ۱۹۱) -base وزن‌های ۴۰۰–۷۰۰ یک فایل وریبل است (`Vazirmatn-Variable-base.woff2`، `font-weight: 400 700`)؛ همان اسکریپت آن را از `tools/fonts/Vazirmatn[wght].woff2` می‌سازد — وزن تازه‌ای در این بازه فایل -base ایستا نمی‌خواهد.
- **ظاهر عمومی (از 2.9.7، بخش ۶۷):** عرض محتوا فقط `var(--hodima-container)` (نه ۱۴۴۰px/90rem ثابت)؛ گردی گوشه با توکن `--hodima-radius-*` و اگر مقدار توکن نیست `calc(Npx * var(--hodima-radius-scale))` (کپسول/دایره بدون ضریب)؛ پس‌زمینه دکمه عمومی `--hodima-button-bg(-hover)`. تب «ظاهر عمومی»: `inc/appearance.php`.
- **امکانات کاربری و ابزارها (از 2.9.8، بخش ۶۸):** `inc/extras.php` — بازگشت به بالا، نوار پایین موبایل (پیش‌فرض خاموش؛ فیلتر `hodima_mobile_nav_items`)، کد سفارشی (نوع فیلد `code`، ذخیره فقط با `unfiltered_html`)، پشتیبان تنظیمات (`admin-post` با nonce). `hodima_settings_sanitize()` داده unslash‌شده می‌گیرد (options.php خودش unslash می‌کند)؛ دوباره `wp_unslash` نکن. آزمون سرتاسری با ورود واقعی: سرور `php -S` روی وردپرس ابزار تست بدون متغیر `HARNESS` (آن ریدایرکت‌ها را می‌بندد).
- **بخش‌های «رسانه» در قالب (از 2.9.4، بخش ۶۴):** شورت‌کدهای `hook_intro|video|voice|faq` افزونه را فقط با `hodima_theme_media_html( $part, $atts )` بخوان (`hodima/inc/media-sections.php`؛ بدون افزونه رشته خالی) و «معرفی + ویدیو» / «پادکست + FAQ» را با `get_template_part( 'template-parts/media/intro-media'|'voice-faq', null, [ 'layout' => … ] )` چاپ کن؛ HTML تازه برای این بخش‌ها در قالب‌های جدا ننویس. پیشوند `hodima_media_*` مال افزونه است؛ تابع قالب با آن پیشوند ننویس.
- **دیدگاه‌ها و نظرات محصول (از 3.9.0، بخش‌های ۱۹۴ تا ۱۹۶):** نمایش فقط در قالب — مقاله/برگه `comments.php`، محصول `woocommerce/single-product-reviews.php` و `woocommerce/single-product/review-meta.php` (بازنویسی قالب ووکامرس؛ `@version` همان قالب اصلی، با ارتقای ووکامرس مقایسه و به‌روز کن)، فهرست مشترک با `hodima_comments_list()` (`inc/comments.php`: «نمایش همه» بعد از `hodima_comments_visible()` رشته — تنظیم `product_reviews_visible`/`blog_comments_visible`؛ قانون `nth-child` با همان عدد فقط از `hodima_comments_collapse_css()` کنار `comments.css` چاپ می‌شود، در CSS ثابت ننویس — برچسب فروشگاه/نویسنده؛ از 3.9.1 خلاصه امتیاز `hodima_reviews_summary()` و نشان خریدار `hodima_review_verified_badge()`؛ «مرتب‌سازی نظرها» 3.9.1 در 3.9.2 به خواست کاربر حذف شد؛ جمع شدن با صفحه‌بندی دیدگاه خاموش است). فرم نظر محصول (3.9.2): «امتیاز شما» و ردیف آخر چک‌باکس کوکی + «ثبت» در `submit_field` همان قالب (ترتیب HTML، نه `order` در CSS). رنگ ستاره‌ها فقط از `--hodima-star-color` (تنظیم `product_star_color`، `hodima_star_color()` در `inc/woocommerce/product-page.php`؛ تعریف نشده = پیش‌فرض هر جا: صفحه محصول `--star-color` رنگ دوم، کارت رنگ اصلی) — ستاره/نوار امتیاز تازه رنگ ثابت نگیرد. شورت‌کد `expand_*_comments/reviews` افزونه را در قالب صدا نزن: فرم را هم جمع می‌کرد و بدون Media بخش حذف می‌شد. فرم ثبت نظر هیچ‌وقت جمع/پنهان نشود. ابزار تست کامنت ندارد: با `HARNESS_OPTS` (بیش از ۳ دیدگاه + پاسخ) بسنج؛ JS وردپرس (`comment-reply`) در وردپرس ابزار تست نیست.
- **تنظیمات قالب** (`hodima/inc/theme-settings/`؛ از 3.6.3 چند فایل تک‌کاره به‌جای یک فایل ۱۹۲۳ خطی، بارگذار `theme-settings.php` به ترتیب ثابت: `fields` ← `structure` ← `reader` ← `register` ← `sanitize` ← `admin-page` ← `admin-fields` ← `front-output` ← `palette` ← `analytics` ← `cache`؛ ترتیب را عوض نکن، ثبت هوک‌ها به آن بسته است؛ بخش ۱۶۱): فیلد جدید در `hodima_settings_fields()` (`fields.php`) با کلید `panel` (قاب در `hodima_settings_panels()`؛ تب از قاب، ترتیب تب‌ها و گروه منوی کناری در `hodima_settings_sections()`). کلید فیلدها = نام ذخیره‌شده؛ عوضش نکن (بخش ۵۶). از 3.0.0 (بخش ۷۳) منوی سطح اول بالای «نمایش»: آدرس فقط با `hodima_settings_url( [ 'tab' => … ] )` و شناسه صفحه `HODIMA_SETTINGS_HOOK` (هرگز `themes.php?page=` یا `appearance_page_`). select رنگ از پالت: `'swatch' => true`؛ قاب جمع‌شونده: `'collapsible' => true` در قاب.
- **منوی هدر (از 3.5.8، بخش ۱۵۶):** والد زیرمنو در موبایل لینک خودش را حفظ می‌کند (`preventDefault` فقط برای والد «#»)؛ باز/بسته‌کردن با `<button class="submenu-toggle" aria-expanded>` از فیلتر `hodima_menu_submenu_toggle` (`inc/header.php`). زیرمنوی بسته باید `visibility: hidden` باشد (نه فقط `max-height: 0`) و قانونش وزن بالاتر از `li:hover/:focus-within > .sub-menu` دسکتاپ داشته باشد؛ منوی تازه را در Chromium با لمس و کیبورد (Tab، Enter، Space) بسنج.
- **هدر چسبان (از 3.5.9، بخش ۱۵۷):** `fixed` با کلاس `is-fixed` و جای هدر با `min-height: var(--header-h)` روی `.site-header-area` (همان متغیر ارتفاع `.header__container`)؛ ارتفاع هدر را با JS نخوان و padding نگذار. `position: sticky` فعلا ممنوع: `html, body { overflow: hidden auto }` در `style.css` body را کانتینر اسکرول می‌کند و هدر نمی‌چسبد؛ برای رفتنش اول باید این overflow (اسکرول افقی iOS) و `overflow-x: clip` (Safari 16+) بررسی شود.
- **حرکت و کاهش حرکت (از 3.6.0، بخش ۱۵۸):** قانون مرکزی پایان `style.css` در `prefers-reduced-motion: reduce` همه transitionها (مدت/تأخیر) و `scroll-behavior` را (`!important`، تنها جای مجاز) فوری می‌کند؛ پس transition تازه خودکار پوشش دارد. `transition: all` ممنوع: فقط ویژگی‌هایی که عوض می‌شوند. `@keyframes`/`animation` تازه باید در همان فایل در بلوک `prefers-reduced-motion: reduce` خاموش شود (`animation: none`)، مگر اسپینر ضروری. `scrollTo`/`scrollIntoView` با `behavior: 'smooth'` فقط با `matchMedia('(prefers-reduced-motion: reduce)')`. بررسی: اسکنر حرکت با `reducedMotion: 'reduce'` (بخش ۱۵۸) باید فقط اسپینر ضروری را نشان بدهد.
- **رنگ ثابت (از 3.6.2، بخش ۱۶۰):** پس‌زمینه سفید ← `var(--hodima-surface, #ffffff)`؛ متن بلند مقاله/دیدگاه ← `--hodima-text-body` (با «رنگ متن» تایپوگرافی عوض می‌شود؛ متن تازه‌ای که باید از آن پیروی کند هرگز `#444`/`#333` ثابت نگیرد). استثناهای عمدی: سفید متن روی رنگ برند، شیشه نیمه‌شفاف، سایه/پرده سیاه، رنگ برند خدمات خارجی (واتس‌اپ، تلگرام، تماس، روبیکا). بررسی: `python3 tools/quality/colors-report.py` (A باید ۰ بماند).
- **نام‌گذاری (از 3.6.4، بخش ۱۶۲):** کلاس/شناسه/متغیر/کلید کش قالب با پیشوند `hodima-`/`hodima_`؛ پیشوند قدیمی `arian` تازه ننویس (مرز `python3 tools/code-map.py`). `.arian-section` و `.arian-scroller` فقط مستعار برای HTML استوری Media ≤ 1.8.6‌اند. هر تغییر نام کلاسی که بین بسته‌ها مشترک است (قالب ↔ Media/SEO) باید مستعار دو طرفه یا HTML با هر دو نام داشته باشد (به‌روزرسانی بسته‌ها هم‌زمان نیست). آزمون ظاهر صفحه اصلی: `HARNESS_HOME=1 tools/wp-harness/visual-compare.sh` (بدونش بخش‌های صفحه اصلی در داده آزمایشی نیستند).

- **انواع بخش صفحه اصلی** (`hodima_home_section_types()` در `inc/home-layout.php`): فیلد تازه با نوع `text|lines|number|tone|select|toggle|category|categories|html|link`؛ **پیش‌فرض خنثی** (بدون متن/نامک مخصوص یک سایت)؛ مقدار قدیمی فقط در `hodima_home_legacy_section_args()` برای شورت‌کدهای قدیمی. گزینه‌های مشترک همه بخش‌ها (`device`، `start`، `end`) بیرون از فیلدهای نوع‌اند. منطق جدا از رندر باشد تا آزمون واحد شود (مثل `hodima_home_product_query_args()`). عنصر تعاملی که با JS ساخته می‌شود (فلش اسکرولر) HTML و کش صفحه را عوض نکند.

## طراحی پیشخوان تنظیمات (از 3.0.8 تا 3.1.2، بخش‌های ۱۰۰ تا ۱۰۸) — قانون
فقط پیشخوان «تنظیمات قالب» (`inc/theme-settings/`)؛ هر قاب یا تب تازه با این قانون‌ها.
- **راست‌چین اول:** فقط خصوصیات منطقی (`inline-start`، `inset-inline-end`؛ نه چپ/راست ثابت)؛ اولین آیتم هر ردیف سمت راست است. استثنا: آیکون راهنما (`scaleX(-1)` تا علامت «؟» فارسی شود). عکس و تست همیشه راست‌به‌چپ.
- **بدون فضای خالی:** فیلدهای مرتبط در یک ردیف (مثلا فونت + اندازه + فاصله خطوط؛ تصویر لوگو + کلیدش). دو قاب کوچک که جدایی‌شان دلیلی ندارد یکی شوند. جابه‌جایی فیلد فقط با کلید `panel` (و `layout` قاب)؛ **نام فیلد و داده ذخیره‌شده عوض نمی‌شود**.
- **چیدمان قاب (`layout`):** `grid` (پیش‌فرض)، `toggles`، `cards` (زیرگروه‌ها)، `rows` (جدول)، `logo` (تصویر + کلید کنار هم)، `swatches` (پالت برند + پیش‌نمایش)، `colors` (کارت رنگ؛ برای فیلد Color و select با `'swatch' => true`)، `tiles` (کاشی وزن فونت)، `'headings' => true` روی قاب rows (کارت «همه تیترها» + جدول اندازه + بخش جمع‌شونده). کارت رنگ: بلوک رنگ بزرگ، برچسب، کد/فهرست، «بازگشت به پیش‌فرض» فقط آیکون؛ در `.hodima-panel--colors` کلید هم کاشی همان ردیف است (`'wide' => false`).
- **راهنما:** راهنمای هر کادر ← آیکون ؟ کنار برچسب (`hodima_settings_tip_html`، حباب fixed با `initTips` در `admin.js`: هاور، فوکوس، کلیک/لمس، Esc؛ متن در HTML می‌ماند و `aria-describedby` دارد). راهنمای بالای قاب: فقط جمله اول دیدنی (`hodima_settings_split_help`). **همیشه دیدنی:** هشدار و شرط مهم (`'help_visible' => true`)، توضیح کاشی کلید روشن/خاموش، فیلد زیرگروه (ردیف جدول). در کارت رنگ آیکون روی گوشه بلوک است.
- **کنترل کمکی (مثل «همه تیترها»):** با `'unsaved' => true` بی‌`name` (ارسال نمی‌شود)؛ `admin.js` مقدار فیلدهای واقعی را می‌نویسد و `input`/`change` می‌فرستد تا نمونه زنده کار کند. قاب جمع‌شونده: `'collapsible' => true`؛ باز اجباری `'force_open' => 'تابع'`، بازشدن با فیلد دیگر `'open_on' => [ ... ]`.
- **کد تکراری نساز:** رندر ردیف/کاشی/سرستون فقط با `hodima_settings_render_items/columns/tiles/headings`؛ CSS عناصر مشترک (مثل `.hodima-tip`) پیش از قاعده‌های خاص‌تر بیاید (`no-descending-specificity` در Stylelint باید بدون خطای جدید باشد).
- **گزینه جدا با `sanitize_callback` (فهرست پویا مثل شبکه‌های اجتماعی، چیدمان صفحه اصلی) باید idempotent باشد:** وقتی گزینه هنوز در پایگاه داده نیست، `update_option` ← `add_option` callback را **دوباره روی مقدار پاک‌شده** اجرا می‌کند؛ اگر فقط شکل خام فرم را بشناسد، اولین ذخیره بی‌صدا خالی می‌شود (باگ 3.2.3/3.2.4، بخش ۱۲۰). آزمون: گزینه را `delete_option` کن و مقدار خام فرم را مستقیم به `update_option` بده (نه مقدار پاک‌شده)؛ خروجی `get_option` را ببین.
- **نقطه‌های شکست پیشخوان:** `1100px` (چیدمان دوستونه ← تک‌ستون)، `782px`، `599px`؛ موبایل ۳۹۰ همیشه دیده شود.
- **چک‌لیست قاب/تب تازه:** (۱) فیلد در `hodima_settings_fields()` با `panel`، قاب در `hodima_settings_panels()`؛ (۲) کنار هم چیده شود، فضای خالی نباشد؛ (۳) راهنما ← آیکون (به‌جز موارد همیشه‌دیدنی)؛ (۴) رنگ فقط کارت پالت؛ (۵) عکس همه ۱۷ تب در ۱۳۰۰ و ۳۹۰ با CSS واقعی راست‌به‌چپ و `admin.js` (روش: `admin-check.sh` ← HTML ← Chromium)، به‌اضافه آزمون رفتار JS (هاور/Esc/کلیک و هر کنترل کمکی)؛ (۶) محدودیت‌ها صریح (ذخیره واقعی فرم و آپلود رسانه در ابزار تست نیست).

## تست ظاهر
برای هر تغییر CSS/JS/HTML قالب `visual-compare.sh` و برای هر تغییر CSS `css-equiv.sh` را اجرا کن؛ بازنویسی هم‌ارز باید «همه نماها یکسان» بدهد و هر تفاوت باید عمدی و در گزارش باشد. ابزار فقط عنصرهای موجود در داده آزمایشی را می‌بیند (ابزار اصلی: صفحه‌های ووکامرس فقط head/footer؛ برای ظاهر فروشگاه `--wc`).
ابزارها (دستورها در `CLAUDE.md` «ابزار تست» و `tools/wp-harness/README.md`): `visual-compare.sh` (`--built`، `--wc`)، `css-equiv.sh`، `important-audit.sh`.

- **متن فقط‌صفحه‌خوان:** کلاس `screen-reader-text` (تعریف در `style.css`) را به کار ببر؛ کلاس تازه نساز. ابزار تست روی صفحه سایت CSS هسته وردپرس را هم بارگذاری می‌کند و ایراد «بدون CSS قالب» را پنهان می‌کند (3.2.2 ← 3.2.6، بخش ۱۲۱)؛ برای عناصر پنهان، صفحه را با حذف `<link>`های `wp-includes` و افزونه‌ها هم در Chromium بسنج.
