# قانون‌های قالب هدیما (`hodima/`)

قالب فقط نمایش است؛ منطق تازه (اسکیما، داده، امنیت، پیشخوان، کش) در افزونه‌ها (اسکیل `hodima-plugins`). تاریخچه هر بخش: `HODIMA-AUDIT.md` با شماره بخش داده‌شده.

## ساختار
- `hodima/`: قالب (نسخه در `style.css`) — فقط نمایش: هدر/فوتر، صفحه اصلی (`home/`؛ چیدمان: `inc/home-layout.php` + `front-page.php`، تب «صفحه اصلی» تنظیمات)، قالب‌های ووکامرس، «نمایش ← تنظیمات قالب هدیما» (`inc/theme-settings/`)

## پالت رنگ برند
**پالت رنگ برند** (توکن‌ها در `hodima/assets/css/tokens.css`؛ مدیر از «تنظیمات قالب ← برند» عوضش می‌کند):
   `#25316a` (اصلی) · `#607bbd` · `#b6c2f3` · `#6a2b9a` · `#a341c8`
   در CSS قالب رنگ برند ثابت ننویس: `var(--hodima-primary, #25316a)` و برای نیمه‌شفاف `rgba(var(--hodima-primary-rgb, 37, 49, 106), 0.1)` (بخش ۵۵).

## قانون‌ها
- **CSS قالب (از 2.9.2، بخش ۶۲):** سورس مدرن (nesting، color-mix با رنگ ثابت…) و مرورگرهای قدیمی با مرحله ساخت (`browserslist` در `package.json`). `@media` فقط بازه‌ای با `<=`/`>=` (مثلا `(width <= 768px)`، مکمل `(width >= 993px)`)؛ `<`/`>` و `@layer` ممنوع (ساخت رد می‌شود). نقطه‌های شکست، شعاع (`--hodima-radius-*`)، فاصله (`--hodima-space-1..9`) و سایه (`--hodima-shadow-*`، `--hodima-ring`) در `tokens.css`؛ مقدار ثابتی که توکن دارد را با توکن بنویس. پیشوند `-webkit-` همیشه **قبل** از خصوصیت استاندارد (برعکسش را minify حذف می‌کند). JS پایین آورده نمی‌شود: `matchMedia` با `min-width`/`max-width` همان عدد CSS. از 2.9.3 (بخش ۶۳): nesting و خصوصیات منطقی چپ/راست در همه فایل‌ها (استثنا: عنصر `direction: ltr` و گوشه‌های radius)؛ زیر انتخابگر چندتایی `&:hover` ننویس (`:is()` می‌شود). `color-mix(var)`، container query، `:has()` و `@layer` تازه ننویس: پایین آورده نمی‌شوند و Chrome 109 (ویندوز ۷) و Safari 14/15 کل قانون را نادیده می‌گیرند؛ رنگ نیمه‌شفاف برند همان `rgba(var(--…-rgb), a)`، رنگ ثابت `rgb(0 0 0 / 0.1)`. `!important` تازه فقط با دلیل (رقیب ووکامرس/افزونه)؛ `tools/wp-harness/important-audit.sh` زائدها را پیدا/حذف می‌کند. از 2.9.5 (بخش ۶۵): CSS همه صفحه‌ها فقط در `HODIMA_COMMON_CSS` (`inc/enqueue.php`؛ ZIP آن را یک فایل `hodima-common.css` می‌کند، handleهای قبلی نام مستعار) و پیش از CSS هر صفحه لود می‌شود؛ CSS درون‌خطی «حیاتی» نساز (CSS قالب مسدودکننده است؛ لایت‌اسپید CCSS خودش را دارد).
- **PHP قالب (از 2.9.0، بخش ۶۰):** هر فایل `declare(strict_types=1)`؛ نوع ورودی/خروجی همه توابع (کال‌بک هوک وردپرس: ورودی `mixed` و تبدیل داخل تابع)؛ baseline PHPCS/PHPStan قالب **خالی** است، پس هر خطای PHP جدید CI را قرمز می‌کند. کلاس/enum جدید در `hodima/inc/classes/` (یک ساختار در هر فایل؛ لود در `hodima_load_theme_files()` در `functions.php`). CSS/JS قالب فقط با `hodima_enqueue_asset( handle، مسیر نسبی )`. `phpcs:ignore` همیشه با نام قاعده و ` -- دلیل`. متغیر در قالب‌های سطح بالا (single-post، archive-blog، template-page-videos، front-page…) پیشوند `hodima_` (در فضای سراسری PHP اجرا می‌شوند).
- **تایپوگرافی (از 2.9.6، بخش ۶۶):** فونت، اندازه/فاصله خطوط/رنگ متن، لینک و تیترهای H1–H6 فقط از توکن‌های `tokens.css` (`--hodima-font`، `--hodima-font-heading`، `--hodima-body-*`، `--hodima-link*`، `--hodima-hN-*`)؛ نام فونت یا اندازه تیتر پایه ثابت ننویس. تب «تایپوگرافی» (`inc/typography.php` + فیلدهای `hodima_typography_fields()`) فقط مقدار متفاوت با پیش‌فرض را بعد از tokens.css چاپ می‌کند (مثل پالت)؛ پیش‌فرض فیلدها = مقدار tokens.css (هر دو را با هم عوض کن). قانون‌های تیتر در `style.css` و `assets/css/editor.css` (ویرایشگر) یکی‌اند. تیتر یک جزء (کارت، قاب کناری) که نباید با پله‌های پایه عوض شود اندازه خودش را بگیرد. **عنوان h1 هر صفحه** (از 2.9.9، بخش ۷۲) اندازه/وزن/رنگ/فاصله خطوط ثابت ندارد و از قانون پایه `h1` می‌گیرد؛ اگر کلاسی که روی h2 هم هست باید روی h1 تنظیم H1 را بگیرد: `var(--hodima-heading-size)` و بقیه متغیرهای سطح.
- **ظاهر عمومی (از 2.9.7، بخش ۶۷):** عرض محتوا فقط `var(--hodima-container)` (نه ۱۴۴۰px/90rem ثابت)؛ گردی گوشه با توکن `--hodima-radius-*` و اگر مقدار توکن نیست `calc(Npx * var(--hodima-radius-scale))` (کپسول/دایره بدون ضریب)؛ پس‌زمینه دکمه عمومی `--hodima-button-bg(-hover)`. تب «ظاهر عمومی»: `inc/appearance.php`.
- **امکانات کاربری و ابزارها (از 2.9.8، بخش ۶۸):** `inc/extras.php` — بازگشت به بالا، نوار پایین موبایل (پیش‌فرض خاموش؛ فیلتر `hodima_mobile_nav_items`)، کد سفارشی (نوع فیلد `code`، ذخیره فقط با `unfiltered_html`)، پشتیبان تنظیمات (`admin-post` با nonce). `hodima_settings_sanitize()` داده unslash‌شده می‌گیرد (options.php خودش unslash می‌کند)؛ دوباره `wp_unslash` نکن. آزمون سرتاسری با ورود واقعی: سرور `php -S` روی وردپرس ابزار تست بدون متغیر `HARNESS` (آن ریدایرکت‌ها را می‌بندد).
- **بخش‌های «رسانه» در قالب (از 2.9.4، بخش ۶۴):** شورت‌کدهای `hook_intro|video|voice|faq` افزونه را فقط با `hodima_theme_media_html( $part, $atts )` بخوان (`hodima/inc/media-sections.php`؛ بدون افزونه رشته خالی) و «معرفی + ویدیو» / «پادکست + FAQ» را با `get_template_part( 'template-parts/media/intro-media'|'voice-faq', null, [ 'layout' => … ] )` چاپ کن؛ HTML تازه برای این بخش‌ها در قالب‌های جدا ننویس. پیشوند `hodima_media_*` مال افزونه است؛ تابع قالب با آن پیشوند ننویس.
- **تنظیمات قالب** (`hodima/inc/theme-settings/`): فیلد جدید در `hodima_settings_fields()` با کلید `panel` (قاب در `hodima_settings_panels()`؛ تب از قاب، ترتیب تب‌ها و گروه منوی کناری در `hodima_settings_sections()`). کلید فیلدها = نام ذخیره‌شده؛ عوضش نکن (بخش ۵۶). از 3.0.0 (بخش ۷۳) منوی سطح اول بالای «نمایش»: آدرس فقط با `hodima_settings_url( [ 'tab' => … ] )` و شناسه صفحه `HODIMA_SETTINGS_HOOK` (هرگز `themes.php?page=` یا `appearance_page_`). select رنگ از پالت: `'swatch' => true`؛ قاب جمع‌شونده: `'collapsible' => true` در قاب.

## یکدستی طراحی (از 3.0.1، بخش ۷۴) — قانون
- **سایت:** کادر فرم و دکمه عملیاتی فقط با `--hodima-control-h` (۴۴px)، `--hodima-control-font` و `--hodima-radius-md`؛ ارتفاع/گوشه ثابت ننویس. قانون عمومی کادرها با `:where()` است تا فاصله داخلی جزء خاص (جستجوی هدر) بماند. رنگ فقط از پالت/توکن (نه نارنجی، سبز، خاکستری دلخواه).
- **پیشخوان تنظیمات:** هر کنترل هم‌ارتفاع `--hs-control-h`، تمام‌عرض ستون؛ رنگ فقط با جزء `.hodima-color` (نوع Color یا select با `'swatch' => true`)؛ کلید بیرون از قاب `toggles` یک ردیف کامل و رنگ کارت ثابت؛ کارت‌های داخل قاب `--hs-radius-md`.
- **پیش از تحویل:** عکس همه تب‌های پیشخوان (CSS واقعی و راست‌به‌چپ پیشخوان، ۱۳۰۰ و ۳۹۰) و اندازه‌گیری دکمه/کادرهای همه صفحه‌ها، نه فقط بخش تغییرکرده.

## ریتم صفحه، باکس، نوار مسیر و کارت‌ها (از 3.4.4 تا 3.4.8، بخش‌های ۱۴۱ تا ۱۴۶ `HODIMA-AUDIT.md`) — قانون و راهنمای تکرار
**هدف:** هر صفحه اندازه‌ی خودش را نداشته باشد. تا 3.4.3 فاصله سکشن‌ها ۵ تا ۱۰، padding باکس ۱۰ تا ۲۵، عرض ۱۲۶۰/۱۲۸۰، گوشه کارت ۸ تا ۱۲، hover ۳ تا ۵، شبکه کارت‌ها ۱px تا ۲۰px بود و همین رقابت قانون‌های هم‌وزن دلیل بیشتر `!important`ها بود.

**توکن‌ها (فقط `assets/css/tokens.css`؛ عدد ثابت در CSS صفحه ننویس):**
| توکن | مقدار | کجا |
|---|---|---|
| `--hodima-section-gap` | ۱۰px (≤۷۶۸: ۸، ≤۴۸۰: ۶) | فاصله بین سکشن‌ها و بالا/پایین قاب |
| `--hodima-section-pad` | ۲۵px (≤۷۶۸: ۲۰، ≤۴۸۰: ۱۵) | padding داخل `.hodima-section-box` |
| `--hodima-grid-gap` | ۱۵px (≤۷۶۸: ۱۰) | فاصله کارت‌ها در همه شبکه‌ها (محصول، مقاله، ویدیو) |
| `--hodima-card-radius` | `--hodima-radius-lg` = ۱۰px × مقیاس گردی | گوشه کارت |
| `--hodima-card-pad` | ۴px | padding داخل کارت |
| `--hodima-card-lift` | ۴px | بالا آمدن hover |
| `--hodima-card-img-radius` | گوشه − padding = ۶px | گوشه تصویر داخل کارت |
| `--hodima-card-shadow` / `-hover` | `--hodima-shadow-xs` / `0 8px 18px rgb(primary / 0.09)` | سایه |
باکس: حاشیه ۱px `--hodima-border-light`، گوشه `--hodima-radius-xl` (۱۲)، سایه `--hodima-shadow-xs`. نوار مسیر: padding ۶/۱۵، گوشه `--hodima-radius-lg` (۱۰). عرض محتوا همه‌جا ۱۲۶۰ (قاب `--hodima-container` + padding ۲۰/۱۵/۱۰). حاشیه رنگی باکس اصلی محصول (`--hodima-border`) استثنای عمدی (تصمیم کاربر).

**کجا تعریف می‌شود:** `assets/css/page-layout.css` (در بسته مشترک `HODIMA_COMMON_CSS`، پس درخواست اضافه ندارد): `.hodima-page-wrapper` (قاب flex ستونی)، `.hodima-section-box` (+ `.blog-page-container`، `.videos-page-container`)، `.section-breadcrumb` (+ خنثی‌کردن margin/اندازه `nav.woocommerce-breadcrumb` ووکامرس) و **کارت مشترک** (`.arian-card`، `.blog-page-card`، `.videos-page-card`، `.product-card-scope ul.products li.product.product`: padding/پس‌زمینه/حاشیه/گوشه/سایه/hover/focus/`prefers-reduced-motion`).

**قانون صفحه یا کارت تازه:**
- صفحه محتوایی: `<main class="hodima-page-wrapper">` و هر بخش `class="hodima-section-box …"` یا `.section-breadcrumb`؛ فاصله را با `margin` ننویس (gap قاب). CSS صفحه فقط رنگ زمینه و چیدمان داخلی می‌گذارد، نه اندازه/فاصله/حاشیه. `--section-gap`/`--cat-*` صفحه‌ای ننویس (حذف شدند).
- کارت تازه: همان شکل را بخواهد → انتخابگرش را به لیست کارت مشترک `page-layout.css` اضافه کن (نه کپی شکل در فایل صفحه) و تصویرش `border-radius: var(--hodima-card-img-radius)` بدون `border-bottom`. نیاز به `&:hover` زیر انتخابگر چندتایی نیست: قانون‌های hover/focus در همان فایل جدا نوشته شده‌اند.
- شبکه کارت: `gap: var(--hodima-grid-gap)` (قبلا کارت‌های فروشگاه/دسته ۱px و محصولات مشابه ۲۰px بودند).
- افزونه‌ها (مثل `video-watch.front.css` در Media): همین توکن‌ها با fallback (`var(--hodima-card-pad, 4px)`)؛ قانون قاب/باکس/نوار مسیر افزونه فقط با `:where()` (وزن صفر) تا در قالب هدیما قانون مشترک برنده شود و بی `!important`.

**استثناها (عمدا دست نخورد):** صفحه ۴۰۴ فقط `main.hodima-page-wrapper` + `section.hodima-section-box` (باکس جدا و هاله حذف شد)؛ سبد ووکامرس باکس بیرونی نمی‌گیرد (باکس‌های خودش را دارد، `page.php`)؛ پرداخت و حساب کاربری داخل باکس مشترک؛ کارت «لینک‌های مرتبط/محصولات مکمل» افزونه SEO (`.hodima-rl__card`، توکن‌های `--rl-*`) به تصمیم کاربر همان‌طور ماند؛ سربرگ فشرده فروشگاه padding عمودی ۱۵ (نه ۲۵).

**روش کار (برای تغییر دوباره، همین ترتیب):**
1. **اندازه‌گیری پیش از تغییر** در Chromium با سه‌گانه: فاصله بین سکشن‌ها، padding/حاشیه/گوشه/سایه/عرض هر باکس، و برای کارت‌ها گوشه/padding/سایه/hover محاسبه‌شده. (نمونه‌ی کد: بخش ۱۴۲ و ۱۴۵ `HODIMA-AUDIT.md`؛ HTML صفحه‌ها در `/tmp/hodima-harness/aout` و `…-wc/aout`، Playwright با route برای CSS قالب.) برای تصمیم کاربر **عکس مقایسه‌ای** بساز و بفرست، نه فقط عدد.
2. **تصمیم کاربر روی عددها** (مرحله ۰) پیش از کد؛ تغییر ظاهری را در CHANGELOG و گزارش «عمدی» بنویس.
3. **مهاجرت صفحه‌به‌صفحه**، هر مرحله یک انتشار: ابتدا توکن + `page-layout.css`، بعد وبلاگ/ویدیو/فروشگاه/دسته/مقاله، بعد محصول، بعد برگه‌ها/سبد/صفحه اصلی/شبکه‌ها، آخر ۴۰۴ و کارت‌ها.
4. **تست هر مرحله:** `bash bin/lint.sh`؛ `visual-compare.sh` و `--wc` (تفاوت ظاهری فقط صفحه‌های عمدی؛ بقیه `pixels: 0`)؛ عکس‌ها را خودت ببین؛ `important-audit.sh` (با `HODIMA_AUDIT_ALLOW_FOREIGN=1`، و `HODIMA_AUDIT_EXTRA_CSS=home/home.css` برای CSSی که صفحه‌ها نمی‌گیرند)؛ بعد از هر تغییر آبشار حتما اندازه‌گیری مجدد.
5. `lint.sh --update-baseline` بعد از برداشتن CSS/`!important` (عدد baseline پایین می‌آید).

**تله‌هایی که پیش آمد (دوباره نیفت):**
- `.hodima-container` (`padding … !important`) باعث می‌شد `padding-block: 40px` برگه‌ها همیشه بی‌اثر باشد (متن چسبیده به هدر)؛ حذف شد. `!important` روی شورت‌هند `padding` کل ویژگی‌های منطقی را هم می‌کُشد.
- قانون هم‌وزن دیرتر در آبشار برنده است: ترتیب فایل‌ها مهم است (`page-layout.css` در بسته مشترک پیش از CSS هر صفحه). قانون عمومی کارت نباید از قانون صفحه‌ی خودش ضعیف‌تر شود؛ تغییر نقطه‌ی شکست/media هم‌وزن را با `li.product.product` (یک کلاس بیشتر) هم‌پا کن، وگرنه قانون پایه موبایل را می‌برد (قیمت کارت ۱۵٫۴←۱۶px شد تا اصلاح شد).
- ووکامرس `.woocommerce ul.products li.product …` (۰،۴،۳) و `margin-bottom ۱em` نوار مسیرش را باید با وزن بیشتر یا `nav.woocommerce-breadcrumb` خنثی کرد، نه `!important`. `@layer` ممنوع است.
- `style.css` قبلا به **همه** `button`ها `color: #fff !important` می‌داد و ریشه‌ی بیشتر `!important`های محلی دکمه‌ها (گالری، مرتب‌سازی، «×» جستجوی زنده) بود؛ حالا بدون `!important`. `display: none !important` دکمه `.button` کارت محصول (`style.css`) لازم است (با تزریق عنصر سنجیده شد).
- برای `!important`ی که عنصرش در داده آزمایشی نیست: عنصر نمونه را در صفحه **تزریق** کن و استایل محاسبه‌شده را با HEAD (`git worktree add … HEAD`) مقایسه کن؛ بدون شاهد برنداشتن.
- کلاس CSS «بی‌مصرف» را قبل از حذف در **همه** بسته‌ها (قالب و ۴ افزونه) و رشته‌های پویا جست‌وجو کن؛ ووکامرس/وردپرس خودش کلاس می‌سازد (سبد، دیدگاه، `sub-menu`…).
- افزونه Media هم کلاس‌های قالب (`hodima-page-wrapper`…) را می‌پوشاند و با `!important` جدا استایل داده بود؛ هر تغییر ریتم را روی صفحه ویدیو (افزونه) هم بسنج.
- `!important`های باقی‌مانده (۲۲ در 3.5.0؛ ۸۷ در 3.4.7 — ۶۵ تای بی‌عنصر با تزریق نمونه سنجیده و برداشته شد، بخش ۱۴۸) عمدی‌اند. برای هر `!important` تازه: نمونه عنصر را در `tools/wp-harness/important-audit-inject.html` بگذار و `important-audit.sh` با `HODIMA_AUDIT_INJECT`، بعد `important-compare.sh` (مقایسه استایل با حالت‌های اجباری) را اجرا کن: فونت سراسری `style.css` (تنظیم تایپوگرافی باید روی افزونه‌ها غلبه کند) و `font-family: inherit` در برابر آن، زنجیره‌ی قدیمی فاصله‌ی خلاصه محصول (`.custom-product-summary > *`، نیاز به بازطراحی با flex/gap و آزمون ۵ نوع محصول)، هدر/صفحه اصلی/محصول/دسته که حالتشان (منوی باز، ویدیوی embed) در داده آزمایشی نیست.

## بخش‌های افقی صفحه اصلی (از 3.1.4، بخش ۱۰۹)
- کارت و باکس اسلایدرهای صفحه اصلی (محصولات یک دسته، جدیدترین، مقالات) فقط با `hodima_home_card_html()` و `hodima_home_cards_section()` (`home/logic.php`) و CSS `.arian-card` / `.arian-product-section`؛ برای یک نوع داده کلاس و CSS جدا (مثل قبلا `modern-blog-card`) نساز؛ تفاوت = پارامتر (قیمت، لینک عنوان، رنگ زمینه `tone`). تصویر کارت همیشه مربع با برش مرکزی؛ فقط یک تصویر صفحه با `hodima_home_claim_priority()` اولویت می‌گیرد.
- **انواع بخش صفحه اصلی** (`hodima_home_section_types()` در `inc/home-layout.php`): فیلد تازه با نوع `text|lines|number|tone|select|toggle|category|categories|html|link`؛ **پیش‌فرض خنثی** (بدون متن/نامک مخصوص یک سایت)؛ مقدار قدیمی فقط در `hodima_home_legacy_section_args()` برای شورت‌کدهای قدیمی. گزینه‌های مشترک همه بخش‌ها (`device`، `start`، `end`) بیرون از فیلدهای نوع‌اند. منطق جدا از رندر باشد تا آزمون واحد شود (مثل `hodima_home_product_query_args()`). عنصر تعاملی که با JS ساخته می‌شود (فلش اسکرولر) HTML و کش صفحه را عوض نکند.

## طراحی پیشخوان تنظیمات (از 3.0.8 تا 3.1.2، بخش‌های ۱۰۰ تا ۱۰۸) — قانون
فقط پیشخوان «تنظیمات قالب» (`inc/theme-settings/`)؛ هر قاب یا تب تازه با این قانون‌ها.
- **راست‌چین اول:** فقط خصوصیات منطقی (`inline-start`، `inset-inline-end`؛ نه چپ/راست ثابت)؛ اولین آیتم هر ردیف سمت راست است. استثنا: آیکون راهنما (`scaleX(-1)` تا علامت «؟» فارسی شود). عکس و تست همیشه راست‌به‌چپ.
- **بدون فضای خالی:** فیلدهای مرتبط در یک ردیف (مثلا فونت + اندازه + فاصله خطوط؛ تصویر لوگو + کلیدش). دو قاب کوچک که جدایی‌شان دلیلی ندارد یکی شوند. جابه‌جایی فیلد فقط با کلید `panel` (و `layout` قاب)؛ **نام فیلد و داده ذخیره‌شده عوض نمی‌شود**.
- **چیدمان قاب (`layout`):** `grid` (پیش‌فرض)، `toggles`، `cards` (زیرگروه‌ها)، `rows` (جدول)، `logo` (تصویر + کلید کنار هم)، `swatches` (پالت برند + پیش‌نمایش)، `colors` (کارت رنگ؛ برای فیلد Color و select با `'swatch' => true`)، `tiles` (کاشی وزن فونت)، `'headings' => true` روی قاب rows (کارت «همه تیترها» + جدول اندازه + بخش جمع‌شونده). کارت رنگ: بلوک رنگ بزرگ، برچسب، کد/فهرست، «بازگشت به پیش‌فرض» فقط آیکون؛ در `.hodima-panel--colors` کلید هم کاشی همان ردیف است (`'wide' => false`).
- **راهنما:** راهنمای هر کادر ← آیکون ؟ کنار برچسب (`hodima_settings_tip_html`، حباب fixed با `initTips` در `admin.js`: هاور، فوکوس، کلیک/لمس، Esc؛ متن در HTML می‌ماند و `aria-describedby` دارد). راهنمای بالای قاب: فقط جمله اول دیدنی (`hodima_settings_split_help`). **همیشه دیدنی:** هشدار و شرط مهم (`'help_visible' => true`)، توضیح کاشی کلید روشن/خاموش، فیلد زیرگروه (ردیف جدول). در کارت رنگ آیکون روی گوشه بلوک است.
- **کنترل کمکی (مثل «همه تیترها»):** با `'unsaved' => true` بی‌`name` (ارسال نمی‌شود)؛ `admin.js` مقدار فیلدهای واقعی را می‌نویسد و `input`/`change` می‌فرستد تا نمونه زنده کار کند. قاب جمع‌شونده: `'collapsible' => true`؛ باز اجباری `'force_open' => 'تابع'`، بازشدن با فیلد دیگر `'open_on' => [ ... ]`.
- **کد تکراری نساز:** رندر ردیف/کاشی/سرستون فقط با `hodima_settings_render_items/columns/tiles/headings`؛ CSS عناصر مشترک (مثل `.hodima-tip`) پیش از قاعده‌های خاص‌تر بیاید (`no-descending-specificity` در Stylelint باید بدون خطای جدید باشد).
- **گزینه جدا با `sanitize_callback` (فهرست پویا مثل شبکه‌های اجتماعی، چیدمان صفحه اصلی) باید idempotent باشد:** وقتی گزینه هنوز در پایگاه داده نیست، `update_option` ← `add_option` callback را **دوباره روی مقدار پاک‌شده** اجرا می‌کند؛ اگر فقط شکل خام فرم را بشناسد، اولین ذخیره بی‌صدا خالی می‌شود (باگ 3.2.3/3.2.4، بخش ۱۲۰). آزمون: گزینه را `delete_option` کن و مقدار خام فرم را مستقیم به `update_option` بده (نه مقدار پاک‌شده)؛ خروجی `get_option` را ببین.
- **نقطه‌های شکست پیشخوان:** `1100px` (چیدمان دوستونه ← تک‌ستون)، `782px`، `599px`؛ موبایل ۳۹۰ همیشه دیده شود.
- **چک‌لیست قاب/تب تازه:** (۱) فیلد در `hodima_settings_fields()` با `panel`، قاب در `hodima_settings_panels()`؛ (۲) کنار هم چیده شود، فضای خالی نباشد؛ (۳) راهنما ← آیکون (به‌جز موارد همیشه‌دیدنی)؛ (۴) رنگ فقط کارت پالت؛ (۵) عکس همه ۱۷ تب در ۱۳۰۰ و ۳۹۰ با CSS واقعی راست‌به‌چپ و `admin.js` (روش: `admin-check.sh` ← HTML ← Chromium)، به‌اضافه آزمون رفتار JS (هاور/Esc/کلیک و هر کنترل کمکی)؛ (۶) محدودیت‌ها صریح (ذخیره واقعی فرم و آپلود رسانه در ابزار تست نیست).

## تست ظاهر
برای هر تغییر CSS/JS/HTML قالب `visual-compare.sh` و برای هر تغییر CSS `css-equiv.sh` را اجرا کن؛ بازنویسی هم‌ارز باید «همه نماها یکسان» بدهد و هر تفاوت باید عمدی و در گزارش باشد. ابزار فقط عنصرهای موجود در داده آزمایشی را می‌بیند (ابزار اصلی: صفحه‌های ووکامرس فقط head/footer؛ برای ظاهر فروشگاه `--wc`).
ابزارها (دستورها در `CLAUDE.md` «ابزار تست» و `tools/wp-harness/README.md`): `visual-compare.sh` (`--built`، `--wc`)، `css-equiv.sh`، `important-audit.sh`.

- **متن فقط‌صفحه‌خوان:** کلاس `screen-reader-text` (تعریف در `style.css`) را به کار ببر؛ کلاس تازه نساز. ابزار تست روی صفحه سایت CSS هسته وردپرس را هم بارگذاری می‌کند و ایراد «بدون CSS قالب» را پنهان می‌کند (3.2.2 ← 3.2.6، بخش ۱۲۱)؛ برای عناصر پنهان، صفحه را با حذف `<link>`های `wp-includes` و افزونه‌ها هم در Chromium بسنج.
