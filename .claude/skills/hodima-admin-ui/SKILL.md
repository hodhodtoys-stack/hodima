# طراحی پیشخوان هدیما (UI/UX)

**خواست کاربر (۳۰ مهر ۱۴۰۵):** کد و ظاهر پیشخوان در سطح جهانی؛ هر وقت کد صفحه‌ای عوض شد، UI/UX همان صفحه هم به این استاندارد برسد. نمونه مرجع: تب «زمان و دفعات» نوتیفیکیشن (Media 2.0.8، `HODIMA-AUDIT.md` بخش ۲۱۵) — قبل: ستونی از عددها با «۰ = خاموش» زیر هرکدام؛ بعد: سؤال ساده، کارت‌های محرک با کلید، شمارنده با واحد، خلاصه زنده.

**دامنه:** فقط همان صفحه/تبی که کار رویش است (بازطراحی بقیه افزونه بدون خواست کاربر نه). قانون‌های فنی پیشخوان (سربرگ `hodima_admin_header()`، `hodima_admin_notice()`/`hodima_admin_flash()`، CSS فقط زیر کلاس صفحه، Dashicons، بدون ایموجی/لینک خارجی) در اسکیل `hodima-plugins` بند «طراحی پیشخوان»؛ این اسکیل *چطور خوب طراحی کنیم* است. سایت (فرانت) قانون‌های خودش را در `hodima-theme` دارد ولی اصول تجربه کاربری پایین آنجا هم معتبر است.

## روند کار
1. **قبل از کد** (تغییر بزرگ ظاهر یا صفحه تازه): نمونه قبل/بعد کنار هم به کاربر نشان بده (Artifact، طرح Design: عکس فعلی + طرح تازه تعاملی) و منتظر تأیید بمان. تغییر کوچک در صفحه‌ای که قبلا با این استاندارد ساخته شده نیازی ندارد.
2. **کد:** اجزای مشترک پایین را به کار ببر؛ جزء تازه‌ای که در بیش از یک صفحه به کار می‌آید به Core (`admin-ui.css`/`admin-ui.js`) برود، نه CSS خود صفحه.
3. **تست:** عکس ۱۳۰۰ و ۳۹۰ قبل/بعد و axe با `admin-shot.mjs` (اسکیل `hodima-notifications` بخش آزمون؛ برای تنظیمات قالب `settings-tab-check.sh`)، کار با صفحه‌کلید، و آزمون «رفت‌وبرگشت فرم» (پایین). عکس‌ها را خودت ببین؛ ناهماهنگی را درست کن.
4. **ثبت:** تصمیم طراحی تازه (جزء، الگو) همین‌جا ثبت شود.

## اصول تجربه کاربری (مهم‌تر از ظاهر)
- **سؤال کاربر، نه نام فیلد:** گروه‌ها با سؤال ساده («چه وقتی باز شود؟»، «به چه کسی؟»، «کجای صفحه؟»)؛ برچسب کوتاه و فارسی روزمره، بدون اصطلاح فنی (UTM فقط داخل توضیح).
- **خلاصه زنده:** فرمی که چند تنظیم با هم رفتار را می‌سازند، بالای خود یک جمله ساده دارد که با هر تغییر به‌روز می‌شود (`.hd-summary`، `aria-live="polite"`). کاربر نباید از روی ده عدد حدس بزند چه می‌شود.
- **کلید به‌جای عدد جادویی:** هرگز «۰ = خاموش/نامحدود». گزینه‌ای که خاموش‌شدنی است = کارت گزینه با کلید (`.hd-opt`)؛ با روشن کردن، پیش‌فرض معقول (`data-hd-opt-default`) می‌گیرد. «نامحدود/یک بار/چند بار» = انتخاب بخش‌بندی‌شده.
- **واحد کنار عدد:** «ثانیه»، «روز»، «٪»، «پیکسل» داخل خود شمارنده (`.hd-num__unit`)، نه در برچسب.
- **انتخاب درست برای تعداد گزینه:** ۲ تا ۴ گزینه کوتاه ← `.hd-seg`؛ گزینه‌ای که با تصویر بهتر فهمیده می‌شود (جا، چیدمان) ← کاشی (`.hd-tiles`)؛ ۵ گزینه یا بیشتر ← `select`؛ روشن/خاموش ← `hd-switch`.
- **افشای تدریجی:** فیلد وابسته فقط وقتی معنا دارد دیده شود (`hidden`، نه `disabled` اگر مقدارش باید بماند: فیلد disabled فرستاده نمی‌شود).
- **پیش‌فرض‌های خوب** و حداکثر یک خط راهنما برای هر فیلد؛ راهنمای بلند پشت ⓘ یا داخل خلاصه.
- **هشدار به‌موقع:** چیزی که جلوی کار را می‌گیرد (بدون عکس نمایش داده نمی‌شود، تاریخ پایان گذشته) کنار خلاصه با `hd-pill--warn`، نه پنهان در راهنما.

## اجزا (Core: `plugins/hodima-core/assets/admin-ui.css` + `admin-ui.js`)
همه زیر `.hd-wrap` (یا `.hd-metabox`)؛ JS فقط رفتار اضافه می‌کند و بدون آن فرم کار می‌کند.

| جزء | نشانه‌گذاری | نکته |
|---|---|---|
| بخش | `section.hd-card` > `.hd-card__head` (Dashicon + `h3.hd-card__title` + `p.hd-card__desc`) | یک سؤال در هر کارت |
| کارت گزینه | `.hd-opts` > `.hd-opt` > `.hd-opt__head` (`.hd-opt__icon` + `label.hd-opt__title` + `input.hd-switch.hd-opt__switch`) + `.hd-opt__body` | کلید با name (مقدار bool خودش) یا بدون name + `data-hd-opt-switch` که فیلد `[data-hd-opt-value]` بدنه را بین «مقدار خاموش» (`data-hd-opt-off`، پیش‌فرض `0`) و آخرین مقدار جابه‌جا می‌کند. بدنه خاموش `inert` و کم‌رنگ (فقط کنترل‌ها، متن خوانا) |
| شمارنده | `.hd-num` > `button.hd-num__btn[data-hd-step="-1"][hidden]` + `input[type=number]` + `button…[data-hd-step="1"][hidden]` + `span.hd-num__unit` | دکمه‌ها بدون JS پنهان؛ `aria-label` «کمتر/بیشتر»؛ `min`/`max` همان تعریف فیلد |
| انتخاب بخش‌بندی‌شده | `fieldset.hd-seg` > `legend` (یا `aria-labelledby`) + `label.hd-seg__opt` > `input[type=radio]` + `span` | رادیو واقعی با همان name/مقدار `select` قبلی: داده عوض نمی‌شود؛ فلش‌ها کار می‌کنند |
| کاشی تصویری | `.hd-tiles` > `label.hd-tile` > `input[type=radio]` + `span.hd-tile__box` (`.hd-tile__art` + `.hd-tile__title` + `.hd-tile__desc`) | تصویر کوچک با CSS خود صفحه (`.hd-tile__art` را صفحه می‌کشد) |
| خلاصه زنده | `.hd-summary` > `.hd-summary__icon` + `.hd-summary__body` (`.hd-summary__label` + `p.hd-summary__text[aria-live]`) + `.hd-summary__warn` | متن را JS خود صفحه می‌سازد؛ بدون JS پنهان (`hidden`) |
| کلید | `input[type=checkbox].hd-switch` (`role="switch"` اختیاری) | |

## ظاهر
- **رنگ:** فقط توکن‌های `--hd-*` (پالت برند؛ اسکیل `hodima-theme` برای پالت). رنگ ثابت تازه نه.
- **فاصله:** مضرب ۰٫۲۵rem؛ داخل کارت ۱٫۵rem (موبایل ۱rem)، بین کارت‌ها ۱–۱٫۲۵rem، بین کارت‌های گزینه ۱rem.
- **سلسله‌مراتب متن:** عنوان کارت ۱rem/۷۰۰، عنوان گزینه ۰٫۸۷۵rem/۷۰۰، برچسب ۰٫۸۱۲۵rem/۷۰۰، راهنما ۰٫۷۵rem/muted. حداکثر سه اندازه در یک کارت.
- **شعاع/سایه:** `--hd-radius` کارت، ۰٫۷۵rem کنترل‌ها، `--hd-shadow`؛ حالت انتخاب = حاشیه `--hd-secondary` + هاله ۴px نیمه‌شفاف (نه رنگ پررنگ کل کارت).
- **ممنوع:** گرادیان پس‌زمینه بزرگ، کارت با حاشیه رنگی یک‌طرفه برای تزئین، ایموجی، سایه سنگین، انیمیشن تزئینی.
- **حرکت:** فقط گذار ۰٫۲s روی رنگ/حاشیه/کلید؛ `prefers-reduced-motion: reduce` = بدون گذار.

## دسترس‌پذیری (WCAG 2.2 AA)
- هدف لمسی کنترل‌ها ≥ ۴۰px (شمارنده و کلیدها ۴۴px).
- هر کنترل برچسب واقعی (`label for`، `legend`، `aria-label` برای دکمه آیکونی)؛ گروه رادیو در `fieldset`.
- `:focus-visible` با `outline: 2px solid var(--hd-accent-light)`؛ هرگز `outline: none` بدون جایگزین.
- کنتراست متن ≥ ۴٫۵:۱ — کم‌رنگ کردن حالت خاموش فقط روی کنترل‌ها، نه متن.
- تب‌ها: الگوی ARIA tabs (فلش راست‌به‌چپ، Home/End)؛ فیلد نامعتبر در تب پنهان، تب خودش را باز کند.
- axe بدون نقض در ۱۳۰۰ و ۳۹۰.

## واکنش‌گرایی
- کادرهای ویرایش نوشته ستون اصلی ≈۷۶۰px دارند (نه ۱۳۰۰): شبکه‌ها با `repeat(auto-fill, minmax(min(100%, Xrem), 1fr))` تا در ۷۶۰ و ۳۹۰ خودشان بچینند.
- `.hd-seg` در عرض کم می‌شکند (wrap)؛ کاشی‌ها حداقل ۹rem.

## ایمنی داده (قانون ۵ CLAUDE.md)
- بازطراحی **نام و مقدار فیلدها را عوض نمی‌کند**؛ کنترل فقط-ظاهری (کلید کارت، حالت شمارش) بدون name یا با name‌ای که ذخیره نادیده می‌گیرد.
- **آزمون رفت‌وبرگشت:** فرم رندرشده را مثل مرورگر بفرست (فیلدهای فعال، چک‌باکس/رادیوی تیک‌خورده، گزینه انتخاب‌شده) و ذخیره کن؛ هیچ متایی نباید عوض شود (نمونه: `notification-tests.php` بخش «کادر ویرایش»).
