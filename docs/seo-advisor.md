# ماژول «دستار سئو» (Hodima SEO ۲.۵.۰ تا ۳.۰.۶)

تحویل کار برای گفتگوهای بعدی (آخرین به‌روزرسانی: ۷ آبان ۱۴۰۵). جزئیات هر مرحله: `HODIMA-AUDIT.md` بخش‌های ۲۵۵ تا ۳۰۷ (آخرین کار: SEO ۳.۰.۲، بخش ۳۰۷؛ برنامه سه‌مرحله‌ای: بخش ۳۰۴ — **برنامه رفع باگ سه‌مرحله‌ای هر سه مرحله انجام شد**). قانون‌های کلی پروژه: `CLAUDE.md`. **برنامه «استفاده کامل از Search Console» تمام شد** (فقط یک مورد را کاربر نخواست؛ پایین).

## خلاصه
با داده Search Console همین سایت (جستجوی وب) برای هر صفحه می‌گوید چه کاری بیشترین کلیک اضافه را می‌آورد و کل سایت را از چند نگاه (رقابت، کلمه، دستگاه، روند، سلامت، ایندکس) بررسی می‌کند. **فقط پیشنهاد و دستور می‌دهد؛ چیزی را در سایت یا Search Console عوض نمی‌کند؛ ادمین خودش اجرا می‌کند.** پیشخوان: «ابزارهای هدیما ← دستار سئو» (`admin.php?page=hodima-advisor`) با ۸ تب، و کادر «دستار سئو» داخل ویرایش نوشته/برگه/محصول/دسته. ماژول `advisor` در «ماژول‌های سئو» روشن/خاموش می‌شود.

| تب | کلید | چه می‌دهد |
|---|---|---|
| پیشنهادها (قبلا «فرصت‌های بهتر شدن») | (پیش‌فرض) | فهرست صفحه‌ها با ایرادها و کلیک بالقوه؛ نماها (همه/محصول/دسته/مقاله)، جستجو، نوع پیشنهاد، حداقل کلیک بالقوه، CSV، نادیده گرفتن |

| آدرس‌های خراب | `health` | آدرس‌های مرده‌ای که هنوز در گوگل‌اند (۴۰۴/ریدایرکت)، صفحه‌های بدون نمایش، پوشش |
| ایرادهای فنی | `crawl` | ایرادهای فنی هر صفحه از خروجی Screaming Frog کنار نمایش گوگل (بدون متا، عنوان، تکراری، کند، ریدایرکت/noindex، لینک ورودی کم، یتیم)؛ فایل‌ها را کاربر در `wp-content/uploads/hodima-advisor/` می‌گذارد |
| وضعیت در گوگل | `indexing` | وضعیت ایندکس آدرس‌های مهم از URL Inspection API |
| در دست انجام | `tasks` | (از ۲.۹.۴) کارهای باز: در حال انجام، هنوز دیده می‌شود/هنوز مانده، برگشته، اثر نداشته؛ با «چه کنید»؛ چیپ «از کدام تب» (`tsource`) |
| انجام‌شده | `done` | کارهای همه تب‌ها (از ۳.۰.۲) با چیپ «از کدام تب» و «وضعیت»؛ سه گام هر کار: انجام دادید ← سنجش همان نوع (گوگل دوباره خواند / صفحه دوباره از سایت خوانده شد / خزش تازه / داده تازه گوگل / آدرس دوباره در سایت) ← نتیجه |

**«انجام شد / رد شد» در هر ردیف (از ۳.۰.۲، `advisor-marks.php`):** پیشنهادها، ایرادهای فنی (تیک برای هر ایراد، از اول زده)، صفحه‌های هم‌کلمه (یک کار برای هر کلمه؛ دکمه‌ها بیرون از `summary` با CSS روی سربرگ)، آدرس‌های خراب (فقط ۴۰۴/ریدایرکت خراب) و صفحه بدون نمایش، وضعیت در گوگل. مورد علامت‌خورده (منتظر نتیجه، برطرف، رد شد) از فهرست پنهان؛ `tasks=all` («نمایش N … علامت‌خورده») همه را با نشان نشان می‌دهد. تب‌های کلمه‌های جستجو، موبایل و کشور و روند فقط آمارند و دکمه ندارند (تصمیم کاربر ۷ آبان ۱۴۰۵).
کادر ویرایش: پنل داده + نمودار «روند کلیک هفتگی» + جمله «قبل/بعد از آخرین ویرایش» + ایرادها با گام‌ها + دکمه‌های وضعیت زیر هر پیشنهاد.

## کلید و تنظیمات
- کلید مخصوص مشاور: ثابت `HODIMA_SEO_ADVISOR_SERVICE_ACCOUNT_JSON` در `wp-config.php` (امن‌تر) ← گزینه `hodima_advisor_sc_key` (کارت «تنظیمات مشاور») ← همان کلید مشترک (دیسکاور یا Google Indexing). فهرست property مشاور جدا (`hodima_advisor_sc_sites`).
- تب «تنظیمات» (`tab=settings`، از ۲.۹.۳؛ پیوند قدیمی `settings=1` به همین تب؛ بدون کلید تب پیش‌فرض): کلید، «حداقل نمایش» (پیش‌فرض ۱٬۰۰۰؛ ذخیره پیشنهادها را فورا دوباره می‌سازد)، «پاک کردن داده‌ها» (جدول‌های دریافتی، وضعیت، نادیده‌ها، آدرس تکراری، بخش‌بندی، روند، سلامت، ایندکس؛ **کلید، تنظیمات، تاریخچه هفتگی و «کارهای من» می‌مانند**).
- `uninstall.php` عمدا نیست: نصب دستی نسخه تازه = حذف + آپلود و داده را می‌برد.
- بررسی ایندکس شاید دسترسی «کامل» حساب سرویس در Search Console بخواهد (نه فقط «محدود»)؛ با گوگل واقعی هنوز آزمون نشده.
